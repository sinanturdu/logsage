# LogSage v0.2.1: dashboard fixes

A patch release for the v0.2 dashboard. Nothing changes in the backend, the database or the configuration. Full list: [CHANGELOG](https://github.com/sinanturdu/logsage/blob/v0.2.1/CHANGELOG.md).

## Fixed

- **The command palette always closes.**
  - It could not be closed once focus had left its panel, for example after a click outside.
  - Escape now closes it from anywhere on the page, and `Ctrl K` / `⌘ K` toggles it.
  - A click or tap on the backdrop, a visible Close button and any route change close it as well.
  - Focus returns to the element that had it before, and opening it twice never stacks two palettes.
  - A footer reads "Up and down to move, Enter to run, Esc to close".
- **A fuller default list in the palette:** with an empty query it offers up to 8 commands for the current page:
  - up to two recent commands;
  - the other page;
  - live tail on or off;
  - Clear filters when filters are active;
  - the two likely next time ranges;
  - project switches;
  - the shortcuts help.
  Typed queries are matched and ranked as before.
- **Error-share strip:** while only error and fatal levels are selected, the share would be 100% everywhere. One line now takes the strip's place: "Error share is not shown while only error and fatal levels are selected." The summary line leaves out the share. Every other level selection keeps the strip and the small-sample rule.

## Root cause

Escape was handled only on the palette's panel, `Ctrl K` could only open it, and the backdrop did nothing, so once focus left the panel, only running a command closed it. The tests missed it because they always pressed keys on the focused palette input.

The lesson, testing keyboard behaviour in a real browser and with raw key events on `<body>`, is recorded in [ADR 0020](https://github.com/sinanturdu/logsage/blob/v0.2.1/docs/adr/0020-command-palette-shortcuts-polish.md).

## Upgrade notes

- **Frontend only:** rebuild the api image, which embeds the dashboard ([ADR 0021](https://github.com/sinanturdu/logsage/blob/v0.2.1/docs/adr/0021-serve-dashboard-csp-runtime-config.md)), and restart `cmd/api`:
  ```bash
  docker compose --env-file .env -f infra/docker-compose.yml -f infra/docker-compose.app.yml --profile app up -d --build api
  ```
  On Windows, `scripts\dev.ps1 up` does the same.
- **No other changes:** no database migrations and no configuration changes. Ingest, the processor and query are unchanged.
- **Coming from v0.1:** read the [v0.2.0 release notes](https://github.com/sinanturdu/logsage/blob/v0.2.1/docs/releases/v0.2.0.md) first.
