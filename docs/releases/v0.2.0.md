# LogSage v0.2.0: accounts and dashboard

v0.2 turns the v0.1 pipeline into something a team can use. It adds accounts, projects with roles and hashed per-project API keys, plus a web dashboard served by the management API for exploring logs, following them live and managing keys. Everything still runs locally with one command.

## What's new

- **Accounts and sessions** ([ADR 0013](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/adr/0013-users-sessions-and-management-api.md))
  - Users with argon2id passwords (12 to 128 characters).
  - Server-side sessions in a `__Host-` cookie, with an idle and an absolute lifetime.
  - Change password signs out your other sessions, and "Sign out of all devices" ends all of them.
  - Login throttling per IP and per email, CSRF checks and an audit log.
- **Projects with roles:** `owner`, `admin` and `viewer`. Non-members get a 404, never a hint that the project exists.
- **Hashed per-project API keys** ([ADR 0011](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/adr/0011-postgres-projects-and-api-keys.md), [ADR 0012](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/adr/0012-project-scoped-authentication.md))
  - Ingest and query keys are stored as a prefix and a SHA-256 hash only.
  - The key decides the project end to end; isolation is covered by end-to-end tests.
  - Keys can be created and revoked with `cmd/admin` or the dashboard.
- **The dashboard** ([ADR 0016](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/adr/0016-dashboard-frontend-stack.md)), served by `cmd/api` on `:8083` ([ADR 0021](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/adr/0021-serve-dashboard-csp-runtime-config.md)):
  - **Log explorer** ([ADR 0017](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/adr/0017-log-explorer.md)): URL state that survives shared links and Back, relative or absolute UTC ranges, level and service facets with counts, search, a trace id filter, and single-line rows with Load more.
  - **Timeline:** two strips over one axis (logs per bucket and the error and fatal share), brushing to select a range, Zoom to selection, a plain-language summary and an "About this chart" note.
  - **Row detail with Same trace** ([ADR 0018](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/adr/0018-row-detail-chips-zoom.md)): the full message, ids, Request and Context attributes, and the other logs of the trace within ten minutes, so an incident's cascade across services is one click away. Also Filter by this trace, Copy as JSON and filter chips.
  - **Live tail** ([ADR 0015](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/adr/0015-live-tail.md), [ADR 0019](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/adr/0019-live-tail-ui-keys-account.md)): Server-Sent Events with resume, read by a fetch-based client with backoff. It pauses while you read and shows its state in words.
  - **API keys screen:** active keys first; a new key is shown once in full, with copyable examples for macOS / Linux and Windows PowerShell that use the configured ingest URL.
  - **Account menu:** change password, sign out of all devices, sign out.
  - **Command palette** ([ADR 0020](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/adr/0020-command-palette-shortcuts-polish.md)): `Ctrl K` / `⌘ K`, plus a `?` shortcuts help generated from the same definition as the key handlers.
  - **Security:** a strict Content-Security-Policy without `unsafe-inline` or `unsafe-eval`, plus `nosniff`, `no-referrer`, a Permissions-Policy, COOP, CORP and `X-Frame-Options: DENY`. HSTS is sent when the API runs behind TLS (`COOKIE_SECURE=true`).
  - **Accessibility:** keyboard paths for every action, visible focus, screen-reader announcements kept polite and rare, and reduced motion respected.

## How to run

On Windows, from PowerShell (needs Docker Desktop; Go 1.23+ only for the demo data):

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1 up
```

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1 seed
```

Open http://localhost:8083 and sign in with the dev login that `up` printed (it is also in `.dev\login.txt`).

Anywhere else, use Docker Compose: copy `.env.example` to `.env` and replace the `change-me` values. Set `COOKIE_SECURE=false` only for plain http on localhost. Then run:

```bash
docker compose --env-file .env -f infra/docker-compose.yml -f infra/docker-compose.app.yml --profile app up -d --build
```

Create a user, a project and keys with `cmd/admin` ([README](https://github.com/sinanturdu/logsage/blob/v0.2.0/README.md)). The full contract is in [architecture.md](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/architecture.md).

## Upgrade notes (from v0.1)

- **Order:**
  1. Run the PostgreSQL migrations (`cmd/admin migrate`, or the compose `migrate` service).
  2. Deploy the processor, which applies the ClickHouse migrations 0003/0004 that add `logs.inserted_at`.
  3. Deploy `cmd/api`, ingest and query.
  The API's live tail needs the new column.
- **`inserted_at`:** rows stored before the upgrade get a fixed old value, so they never appear in a live tail. Searches are unaffected.
- **Legacy static keys are off by default (breaking).** `INGEST_API_KEY` and `QUERY_API_KEY` are ignored unless `ALLOW_LEGACY_STATIC_KEYS=true`. A deployment that relies on them must set that flag until its clients use per-project keys. The static keys are removed in v0.3.
- **The comma is now a separator in `service`:** `service=a,b` means "a or b" (at most 20 names), also on `/v1/logs`. A service name containing a comma can no longer be searched exactly.
- **New settings for `cmd/api`:**
  - `DATABASE_URL`.
  - All of `CLICKHOUSE_URL`, `CLICKHOUSE_DB`, `CLICKHOUSE_USER` and `CLICKHOUSE_PASSWORD`.
  - The session settings, and `WEB_ENABLED` and `PUBLIC_INGEST_URL`.
  - See [.env.example](https://github.com/sinanturdu/logsage/blob/v0.2.0/.env.example).
- **Docker build context:** it is now the repository root (`docker build -f backend/Dockerfile .`), because the image also builds the dashboard.

## Benchmark summary

Local Docker Desktop on a Windows laptop (i7-10750H, 15.8 GB RAM). It is not a production benchmark; details are in [benchmarks.md](https://github.com/sinanturdu/logsage/blob/v0.2.0/docs/benchmarks.md).

| Metric | Result | Requirement |
|---|---|---|
| Ingest throughput (v0.1 series) | 15k–70k events/s for 1–64 senders | N2 10k events/s: met |
| Ingest at a steady 10k events/s, v0.2 regression check | 3 runs of 15 s, per-project key, concurrency 16: p50 3.2–3.8 ms, p99 6.3–7.4 ms, max 14.6 ms, all `202` | N1 < 50 ms: met |
| No loss | accepted == stored in all 3 regression runs (450,200 events, lost 0); bursts at maximum rate in v0.1 also lost 0 | no silent loss: met |
| 24h search over 1M rows (v0.1 series) | p99 ≤ 342 ms (76 ms with a service filter) | N4 < 2 s: met for that dataset |

The regression check matches the v0.1 re-run (p50 about 3 ms, p99 5.9–7.9 ms). Per-project key verification (cached for 30 s) adds no visible cost at this rate.

## Known limitations

- **Per-instance state:** the login throttling, the live tail connection limits and the query caps are kept per API instance. Several instances behind a load balancer each enforce their own limits.
- **Sessions:** they live in PostgreSQL and are checked on every request. There is no session list in the dashboard, only "sign out of all devices".
- **No email:** no email verification, no password reset by email and no MFA. Operators reset passwords with `cmd/admin set-password`.
- **One ClickHouse user:** `cmd/api` and `cmd/query` read with the same ClickHouse user as the processor writes with; a read-only user is planned.
- **Soft backpressure:** ingest answers `429` from a cached stream length, so the queue can overshoot its limit briefly (see the v0.1 notes).
- **TLS:** LogSage does not terminate TLS. Put a reverse proxy or load balancer with TLS in front of `cmd/api` and ingest, and set `COOKIE_SECURE=true`, which also turns on HSTS.
- **Old rows in the live tail:** rows stored before the upgrade, and logs that arrive more than 10 minutes late, are not streamed live; they are still searchable.
