# LogSage v0.1.0: ingest and search

v0.1 delivers the core pipeline: applications send logs over HTTP, LogSage queues them in Redis, stores them in ClickHouse, and makes them searchable through a read-only API. Everything runs locally with one Docker Compose command.

## Features

- **Ingest API** (`POST /v1/ingest`)
  - Backpressure: `429` with `Retry-After` while the queue backlog is at its limit; `GET /stats` with accepted, rejected and failed counts.
  - Accepts JSON batches of up to 1000 events and 1 MiB.
  - Strict validation: RFC3339 timestamps, five levels, required service and message, limits on message, trace ID and attributes.
  - Rejects the whole batch when any event is invalid and names the failing index.
  - Static API key compared in constant time and never logged. Returns `202 {"accepted": N}`.
- **Queue**: Redis Streams. A batch is one pipelined round trip. The stream is trimmed only below what the processor has finished with, and ingest answers 429 when the backlog reaches its limit, so nothing is silently dropped.
- **Processor**: one consumer group, so instances share the work.
  - Recovers its own pending entries on start and claims entries left idle by crashed consumers.
  - Writes batches of 1000 rows or every 1 s to ClickHouse and acks only after a successful insert.
  - Retries with backoff and stops reading while ClickHouse is down. Unusable entries go to a dead-letter stream.
  - Duplicates from redelivery collapse in ClickHouse (`event_id` + `ReplacingMergeTree`).
- **Query API** (`GET /v1/logs`)
  - Time range plus optional level, service, case-insensitive text and trace ID filters, newest first, with keyset cursor pagination.
  - Uses a separate read key; the ingest key does not work here.
  - Every query goes through one project-scoped builder with server-side parameters and runs `readonly=1` with time and row limits.
- **Operations**
  - `/healthz` and `/readyz` everywhere, plus processor `/stats`.
  - Graceful shutdown that flushes the current batch.
  - All configuration through environment variables with fail-fast validation.
- **Tooling**: `cmd/loadgen` for ingest load, query benchmarks and a demo stream with a simulated incident. Unit tests, plus integration tests against real Redis and ClickHouse in CI.

## How to run

```bash
cp .env.example .env    # replace the change-me values
docker compose --env-file .env -f infra/docker-compose.yml -f infra/docker-compose.app.yml --profile app up -d --build
```

Then send events to `http://127.0.0.1:8080/v1/ingest` and search at `http://127.0.0.1:8082/v1/logs`. Examples are in the [README](../../README.md#api-examples), and the full contract is in [architecture.md](../architecture.md).

## Fixed before release

- **No more silent loss under bursts** (ADR 0010). Before this fix, `XADD MAXLEN ~` trimmed entries nobody had read: 22.9% of a 10-second burst was lost while `/stats` looked healthy. Now publishing never trims, the processor trims only what every consumer group acknowledged, ingest applies backpressure (`429` with `Retry-After`), and Redis refuses writes at its memory cap instead of evicting. Verified: three 10-second maximum-rate bursts and a 30-second burst with backpressure engaged stored every accepted event (lost 0).

## Known limitations

- **Backpressure is soft.** Ingest answers `429` once the cached stream length reaches `INGEST_MAX_STREAM_LEN`, but the cache is up to 500 ms old, so the stream can overshoot the limit by about ingest rate × refresh interval (measured: +27.5% at 20k events/s on a 20k limit, +150% when 50k events arrived within one refresh). Clients must retry `429` themselves. The Redis memory cap (1 GB, `noeviction`) is the hard backstop and turns into `503`.
- **Searches without a `service` filter read the whole time window.** That is fast at 1M rows per day but would not stay under 2 s at 10k events/s sustained (about 864M rows per day) without an index on `timestamp`.
- **Text search is a scan**, bounded only by the time window (max 168h) and the query timeout.
- **One static key per API and one project** (`"default"`). There are no accounts, per-project keys or key rotation yet.
- **Delivery is at-least-once.** Read with `FINAL` (the query API does) for exact results; `FINAL` costs up to several times more on freshly ingested, unmerged data.
- **Unknown JSON fields are rejected** by ingest, so clients must match the server version.
- **No metrics endpoint (Prometheus) yet**; `/stats` and logs only.
